# Production Deployment Guide — Curb Connect

## Before Launch

### 1. Make the GitHub Repository Private

**Why:** The repo is currently public but licensed as proprietary. Making it private prevents unauthorized copying of your code.

**Steps:**
1. Go to https://github.com/samadalam481470sa-cmd/curb-connect/settings
2. Scroll to **Danger Zone** > **Repository visibility**
3. Click **Change visibility**
4. Select **Make private**
5. Confirm by typing the repository name
6. Click **I understand, change repository visibility**

After this, only you and invited collaborators can access the code.

### 2. Set Up Email Sending (SMTP)

**Why:** New users must verify their email to start their free trial. Without SMTP, emails are written to a local folder and never delivered, locking users out forever.

**Steps:**

#### Option A: Gmail (recommended for small deployments)

1. Create a [Google App Password](https://support.google.com/accounts/answer/185833):
   - Use your personal Google Account or a service account
   - Enable 2-factor authentication on the account
   - Go to https://myaccount.google.com/apppasswords
   - Select **Mail** and **Windows Computer**
   - Copy the 16-character password

2. In Render dashboard for the **curb-connect-api** service:
   - Go to **Environment** tab
   - Find or add `SMTP_URL`
   - Set the value to: `smtps://your.email@gmail.com:YOUR_APP_PASSWORD@smtp.gmail.com:465`
   - Example: `smtps://ai@example.com:abcd1234efgh5678@smtp.gmail.com:465`
   - Click **Save**

#### Option B: AWS SES, SendGrid, or other SMTP provider

Format: `smtps://username:password@smtp.example.com:port` or `smtp://username:password@smtp.example.com:port`

Examples:
- SendGrid: `smtps://apikey:SG.xxxxx@smtp.sendgrid.net:465`
- AWS SES: `smtps://AKIAIOSFODNN7EXAMPLE:xxxx@email.us-east-1.amazonaws.com:465`

### 3. Verify After Deployment

1. Deploy the latest main branch to Render
2. Test the full sign-up flow:
   - Create a new password account at https://curb-connect-web.onrender.com/sign-up
   - Check the email inbox for the verification link
   - Open the link and verify the email
   - Confirm the trial starts and you can access the company

## Render Environment Variables

These are set in the Render Blueprint (`render.yaml`) and dashboard:

**Set once in Render dashboard (sync: false):**
- `SMTP_URL` — SMTP connection string for outgoing email
- `MAIL_POSTAL_ADDRESS` — Legal postal address in email footers (CAN-SPAM)
- `MICROSOFT_TENANT_ID` — Default: `common` (allows any Microsoft account)
- `MICROSOFT_CLIENT_ID` — Microsoft OAuth client ID
- `MICROSOFT_CLIENT_SECRET` — Microsoft OAuth client secret
- `GOOGLE_CLIENT_ID` — Google OAuth client ID
- `GOOGLE_CLIENT_SECRET` — Google OAuth client secret
- `STORAGE_ENCRYPTION_KEY` — Base64-encoded 32-byte AES key for uploads (auto-generated first time)

**Auto-generated by Render:**
- `SESSION_SECRET` — Session cookie encryption key
- `APP_DB_PASSWORD` — PostgreSQL password for the app role

## Sign-In Methods

After deployment, users can sign in via:

1. **Username/Password** — Create an account with email verification
2. **Microsoft** — Requires `MICROSOFT_CLIENT_ID` and `MICROSOFT_CLIENT_SECRET`
3. **Google** — Requires `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` (not yet set, so unavailable)

## Monitoring

Watch for errors in Render logs:
- Password sign-up failures: check for "emailVerified" or "verification" errors
- Mail delivery failures: look for SMTP connection errors in logs
- Trial/access issues: search logs for "trial_expired" or "access denied"

## Troubleshooting

**Users can't sign up:**
- Check if SMTP_URL is set. If not, password accounts auto-verify (no email needed).
- If SMTP_URL is set but users don't get the email, check Render logs for SMTP errors.

**Users verify but trial doesn't start:**
- Check if the verification link was opened (look for `email.verification` in API logs).
- Confirm the email was normalized correctly (no typos, case-insensitive, +tags removed).

**Service keeps waking up:**
- Free Render plans sleep after 15 minutes of inactivity. The first request wakes them (~1 minute).
- Upgrade to a paid plan to prevent sleep.

## Security Notes

- All user passwords are hashed with scrypt (cost factor 15).
- Database role `fieldline_app` is restricted: cannot modify billing fields, cannot read platform-only tables.
- Session cookies are HttpOnly, Secure (over HTTPS), and SameSite=Strict.
- CSRF protection via Origin header validation on cross-site POST requests.
